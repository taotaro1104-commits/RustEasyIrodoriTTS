# M2b-2 話者（アップロード・登録・名前変更・削除・声の試作） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 画面から、音声ファイルを取り込み（`/api/upload`）、話者として登録・名前変更・削除でき（`/api/voice` `/api/voice/rename` `/api/voice/delete`）、声の試作（`/api/design` `/api/design-registration`）の候補を試聴して話者に採用できる。

**Architecture:** 取り込みは `irodori-core::audio` の symphonia デコード（公開化）→ 24 kHz モノラル 24bit WAV（`temp/uploads/`）→ `Assets` に登録して鍵を返す。話者の保存は `irodori-store` の `Store`（`voices/index.json`、v2.0 の `easy_voices.py` と同じ規則）。声の試作は `JobManager` に `kind="design"` のジョブを足し、既存のワーカー・取消・進捗をそのまま使う（`Synthesizer` は変更しない）。

**Tech Stack:** Rust、axum（`multipart`）、symphonia（core のみ）、hound。

**Spec:** `docs/superpowers/specs/2026-11-13-m2-server-and-editor-design.md`（§5 M2b、§6 の design、§8 アップロード、§10 安全対策）。振る舞いの正解は `EasyIrodoriTTS_v2.0/EasyIrodoriTTS_v2.0/` の `easy_voices.py`、`easy_web.py`（`upload` `voice*` `design*`）、`easy_service.py`（`design`）。画面は v2.0 の `editor/app.js`（登録ダイアログ。無改修で動くことが目標）。

## M2b の分割（この計画は 2/3）
- M2b-1（完了）: 生成ジョブ・停止・進捗。
- **M2b-2（この計画）**: 上記 ＋ M2a からの持ち越し 4 件（Task 7）。
- M2b-3: モデルの自動ダウンロード。

## Global Constraints
- ユーザー向け文言は v2.0 と同じ日本語（各タスクに明記）。想定外の失敗の詳細はログだけに出す。
- 取り込みの拡張子は `.wav .mp3 .flac .ogg .m4a .mp4`。**`.webm` は 501「未対応です（.webm は読み込めません。wav / mp3 / flac / ogg / m4a / mp4 を使ってください）。」**。それ以外は 400「音声ファイルを選んでください。」。上限は **100 MB**（超えたら 400「音声は100MB以内にしてください。」）、長さは **1〜120 秒**（400「音声は1～120秒にしてください。」）、デコード失敗は 400「音声を読み込めません。形式を確認してください。」。
- 取り込んだ音声は `temp/uploads/<uid>.normalized.wav`（**24 kHz・モノラル・24bit**）。元ファイルは成功・失敗にかかわらず消す。保存名にクライアントのファイル名を使わない。
- 話者の規則（`easy_voices.py` のとおり）: 名前は前後の空白を除いて **1〜80 文字（Unicode のコードポイント数）**、モデルは `models::ALLOW_LIST` のどれか、`caption` は先頭 **2000 文字**で切る。更新時は `revision` が一致しないと 400「話者が更新されています。一覧から読み直してください。」。保存のたびに `revision+1`、**`sound_revision = revision`（名前だけの変更でも）**。一覧は「他の話者＋更新した話者」の順（更新した話者は末尾へ移る）。名前変更だけは `sound_revision` が無ければ旧 `revision` を入れ、音が変わらない限り `sound_revision` を上げない。削除は一覧から外すだけで**ファイルは消さない**（生成待ちの要求が参照するため）。
- 参照音声は 1〜120 秒。話者に採用する WAV は 24bit PCM に書き直して `voices/<id>/<uid>.wav` へ置く（`audio` は `store.root` からの相対パス）。
- 試作の文章は推定 25 秒以内（`split_text` が 2 つ以上に割れたら 400「声の試作には推定25秒以内の短い文章を入力してください。」）。登録用の定型文は v2.0 の `REGISTRATION_SAMPLE_TEXT`（`easy_service.py:18`）をそのまま使う。
- 他のジョブが動いている間の試作は 400「現在の生成が終わってから実行してください。」。
- 1 ファイル 400 行以内（最大 800）。`cargo test -p irodori-core -p irodori-store -p irodori-app` は常に緑。実モデルのテストは `--release` で環境変数があるときだけ。`cargo test --workspace`（debug）を `IRODORI_*` 環境変数つきで走らせない。

## Review Focus
1. 取り込み: 0 バイト／拡張子だけ `.wav` の壊れたデータ／0.5 秒／121 秒超／100 MB 超 → それぞれの日本語メッセージで拒否され、`temp/uploads` に何も残らない（Task 2, 3）。
2. 名前の境界: 空白だけ・80 文字ちょうど・81 文字・絵文字や結合文字を含む日本語 → コードポイント数で数える。JSON の `name` が文字列でない値も 400（Task 2, 4）。
3. 話者を登録し直した直後に、古い版を参照する生成待ちのカードがある → 古い WAV は消えておらず、署名は新しい `sound_revision` で「再生成が必要」になる（Task 2, 4）。
4. 試作: 停止 → 「停止」で候補なし／別ジョブの `job` や候補でない `asset` を `/api/voice` に渡す → 400「生成候補を選び直してください。」／未登録の `references` 鍵 → 400「音声が見つかりません。もう一度追加してください。」（Task 5, 6）。
5. 保存先に書けない（空き容量・権限）→ `voices/index.json` は変わらず、途中でできた WAV は消える（Task 2）。`voices/index.json` が壊れていれば上書きしない（M2a の規則のまま）。
6. 巨大な JSON 本文・ハンドラの panic → 画面に出せる JSON のエラーが返り、サーバは落ちない（Task 7）。

## 持ち越し（この計画の外）
- 話速（`speed` ≠ 1.0）・自動書き出し・まとめ保存・整理・入力済データは M2c。モデルの自動取得は M2b-3。
- 取り込みの音声に無音・ほぼ無音のものが来た場合の事前警告は v2.0 にも無いので入れない（生成時に core が `SilentReference` を返す）。
- 参照音声が複数の話者・複数参照の生成は未対応のまま（`RealSynth` が 1 つだけ受け付ける）。
